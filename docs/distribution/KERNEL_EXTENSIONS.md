# Drivers y extensiones del sistema
Fuentes: [v4l2loopback-dkms](https://archlinux.org/packages/extra/any/v4l2loopback-dkms/), [v4l2loopback upstream](https://github.com/v4l2loopback/v4l2loopback), [Iriun AppImage comunitario](https://github.com/sharno/IriunWebcam-AppImage), [signed modules](https://wiki.archlinux.org/title/Signed_kernel_modules), [NVIDIA transition](https://archlinux.org/news/nvidia-590-driver-drops-pascal-support-main-packages-switch-to-open-kernel-modules/), [sysext](https://www.freedesktop.org/software/systemd/man/latest/systemd-sysext.html).
Contenedores Linux normales comparten kernel del host, módulo requiere ABI exacta y privilegios del host. No fingir aislamiento de módulo: código kernel tiene acceso privilegiado. Preferir incluir v4l2loopback compilado y firmado por imagen, cargar solo cuando necesario, opción de cámara virtual autorizada. Iriun user-space (AppImage/AUR comunitario o upstream) requiere /dev/video apropiado, red y permisos; confirmar licencia, no redistribuir binario propietario sin derecho. OBS virtual camera prueba adicional. No afirmar funcionamiento de Iriun hasta prueba. VirtualBox/ZFS/otros DKMS opcionales y auditados; WireGuard in-tree cuando kernel soporta.
Extensión host: manifest nombre/versión, kernel release exacto, headers, source/license, dependencias, firma/trust, initramfs need, device permissions, compatibility matrix, pruebas. Compilar contra kernel destino en build/staging, no en activo; incluir módulos, depmod/initramfs/UKI según caso, probar Secure Boot y política de firma de módulos. Secure Boot no garantiza por sí solo enforcement de módulos; decidir política y testear sin bypass. Activar en despliegue siguiente con consentimiento privilegiado independiente. Módulos no confiables no soportados; usuario puede elegir despliegue personalizado bajo responsabilidad, sin conceder a agentes privilegios arbitrarios. sysext candidato para extensiones userspace versionadas, no vía universal para módulos tempranos. Rollback recupera kernel/módulos pareados; revisar persistencia de configuración y claves.
NVIDIA: RTX 3090 Ampere candidato open kernel modules + userspace propietario de misma versión; Pascal/Maxwell (GTX 1050 Ti) ya no soportados por 590+, evaluar rama legacy 580xx mientras mantenida o Nouveau con limitaciones. No prometer driver universal. Intel/AMD Mesa, firmware y kernel por imagen. CUDA/containers: driver host compatible y userspace runtime según requisitos; Flatpak GL extension matching; multilib/Steam evaluar. GPU pressure: preservar compositor, liberar cachés, degradar efectos con histéresis, restaurar calidad, no matar IA/juegos. Pruebas D06/D07 y P17.
