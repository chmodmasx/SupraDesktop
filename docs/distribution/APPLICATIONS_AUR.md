# Applications y AUR
Fuentes: [AUR](https://wiki.archlinux.org/title/Arch_User_Repository), [Distrobox](https://github.com/89luca89/distrobox), [Flatpak](https://docs.flatpak.org/en/latest/basic-concepts.html), [AppDir](https://docs.appimage.org/reference/appdir.html).
Vista Applications aceptada: ~/Applications reales para portables, vista virtual unificada por AppRegistry. Flatpak/flatpakref delegar gestor; AppImage/AppDir copiar/validar/registrar sin ejecutar al copiar; SupraBundle futuro opcional. Entradas de base son read-only gestionadas por imagen; AUR exportado distingue proveedor y scope. No .deb en plan oficial. No gestor de paquetes nuevo. Datos XDG conservados por defecto al quitar. Registrar update por proveedor.
## AUR
1. AUR integrado: rootless Distrobox/Podman con acceso explícito a recursos, para software confiable; Distrobox comparte home y no es sandbox. Contenedor Arch rolling separado puede tener incompatibilidad gráfica/driver con host congelado; fijar imagen/digest y verificar GPU, Wayland, audio y portales.
2. AUR restringido: entorno con home propio y montajes mínimos, red/dispositivos según permiso, sin sockets privilegiados ni acceso global al bus/host. Rootless no equivale a aislamiento perfecto; evaluar VM para código no confiable. Compatibilidad no garantizada. Construcción en entorno separado con revisión de PKGBUILD y fuentes; build limpio no es frontera de seguridad. No ejecutar scripts no revisados en host. Exportación de desktop entries validada, no autoejecución.
3. AUR host excepcional: solo necesidad demostrada (driver, servicio, integración imposible en user-space); revisión explícita y despliegue nuevo desde snapshot coherente. No overlay general ni pacman -Syu en imagen activa; identificar despliegue personalizado como no soportado oficialmente, ofrecer rollback y recuperación. AUR no equivale a catálogo curado; usuario asume riesgo informado, sin desactivar protecciones.
Separar permisos del agente de los del usuario, no autorizar instalación privilegiada genérica. Pruebas de build, launch/export, GPU, portales, permisos, actualizaciones del contenedor y eliminación sin daño a datos. No pruebas realizadas.
