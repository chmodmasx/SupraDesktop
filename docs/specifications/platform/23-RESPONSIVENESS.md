# P23 — Aplicaciones no respondientes
Fuentes: [xdg-shell ping/pong](https://wayland.app/protocols/xdg-shell), [Qt application watchdog](https://doc.qt.io/QtApplicationManager-6.10/watchdog.html), [systemd watchdog](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html), [kernel PSI](https://docs.kernel.org/next/accounting/psi.html).
## Diseño
xdg_wm_base ping/pong verifica respuesta del cliente al protocolo, no garantiza que UI o worker estén sanos; no confundir app idle sin frames con bloqueo. Estado responsive/suspect/unresponsive/recovered/unknown; timeout adaptativo y confirmaciones múltiples según carga, suspend/resume, debugging y GPU. XWayland _NET_WM_PING cuando soportado. Heartbeat/watchdog solo para servicios propios que lo implementan, no para todas apps. Separar caída proceso, loop bloqueado, GPU fence y presión sistema. PSI/cgroup diagnósticos complementarios, no inferir culpa automática.
UI equivalente a Force Quit: indicar app, estado, esperar, intentar cierre normal, forzar con consentimiento explícito y advertencia de datos no guardados; validar identidad/unidad y scope. No terminar apps del usuario automáticamente por timeout. Shell propio con supervisor, backoff y modo seguro; lock fail-closed. No reiniciar compositor por un cliente.
P23a: cliente de prueba no responde y luego recupera; b: suspend, debugger, carga CPU/GPU, idle y falso positivo; c: close graceful/force en fixture sin documentos reales; d: servicio propio cae y reinicia; e: diagnóstico correlacionado, interfaz accesible. NOT_RUN.
