# P20 — Registro y ciclo de aplicaciones
Fuentes: [Desktop Entry](https://specifications.freedesktop.org/desktop-entry/latest-single/), [systemd desktop integration](https://systemd.io/DESKTOP_ENVIRONMENTS/), [xdg-activation](https://wayland.app/protocols/xdg-activation-v1), [Flatpak exports](https://docs.flatpak.org/en/latest/conventions.html).
## Diseño
AppRegistry distingue app lógica, instalación (proveedor/scope/ref/path), instancia de lanzamiento, proceso/unidad, toplevel. IDs de escritorio XDG, app_id Wayland, Flatpak, bundle metadata, XWayland hints son señales de asociación no prueba de identidad. Autorización con credenciales y relaciones verificadas; no usar título o PID aislado. Detectar apps instaladas y fuentes externas, reconciliación de watchers y cambios. Una app puede tener varias ventanas, cero ventanas, múltiples procesos y múltiples instancias. Estados discovered/installed/launching/running/windowless/exiting/stopped/unknown; hung separado como señal no definitiva. Dock y Search clientes del mismo registro.
Launcher valida desktop entry Exec conforme spec (no shell arbitrario), DBusActivatable y activación xdg con token legítimo. Delegar Flatpak y APT; portables ver A00. Usar systemd user app-*.service/scope según entorno y convenciones, no asumir que todas apps externas lanzadas pertenecen a unidad propia. Separar close window, hide, minimize, quit graceful, force quit con consentimiento. No finalizar proceso no identificado, no enviar señal a todo cgroup sin validar ownership. Background apps y autostart según XDG. Restauración cooperativa, no autoejecución de acciones sensibles.
P20a: launch native/Flatpak/AppImage/DBus y asociación de ventanas; b: zero/multi-window, single instance, reinicio, launch timeout y foco; c: close/quit/hide y proceso externo; d: crash, cambio instalación y reconciliación; e: actividad y permisos de acciones, no PID reuse. NOT_RUN.
