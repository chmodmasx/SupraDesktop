# P21 — Eventos y concurrencia
Fuentes: [calloop](https://docs.rs/calloop/latest/calloop/), [Tokio bounded mpsc](https://docs.rs/tokio/latest/tokio/sync/mpsc/), [Tokio channels](https://tokio.rs/tokio/tutorial/channels).
## Diseño
Compositor: event loop calloop y mutación de estado autoritativo serializada; callbacks breves, trabajo disk/network/index/encoding fuera del loop; render scheduling separado de tareas background. No await de operaciones no acotadas en hilo de entrada o presentación. Worker pools limitados, Tokio servicios, canal de resultados al dueño con revisión y cancelación. Evitar lock global, no mantener locks durante llamadas a otros procesos. No asumir lock-free siempre más rápido.
Eventos tipados con session/resource ID, schema version, seq por dominio, monotonic timestamp y correlation ID; snapshot + cursor/revisión para reconexión. No global total ordering innecesario; describir causalidad y revisiones. Colas acotadas, prioridad por clase: input/lock/focus crítica (orden, no descartar transiciones), estado último valor coalescible, telemetría muestreable, trabajo durable según dominio. Si consumidor lento: gap explícito y resync, no perder cambios silenciosamente. Evitar head-of-line blocking, backpressure y límites por cliente. Operaciones async con deadline, cancelación, idempotencia/reconciliación; no prometer exactly-once. Reloj monotónico para duración, wall clock para presentación/auditoría.
P21a: burst input y render mientras indexa; b: consumidor lento, overflow/resync, cambios ordenados; c: timeout, cancelación, restart y resultados stale; d: CPU/RAM y p95/p99; e: fallos de servicios, lock sigue seguro. NOT_RUN.
