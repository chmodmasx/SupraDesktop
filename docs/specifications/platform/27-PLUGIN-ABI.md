# P27 — Plugins y ABI
Fuentes: [Rust Reference ABI](https://doc.rust-lang.org/reference/items/external-blocks.html), [Wasmtime component model](https://docs.wasmtime.dev/component-model.html), [WASI](https://github.com/WebAssembly/WASI), [WIT](https://component-model.bytecodealliance.org/design/wit.html).
## Hallazgo
Rust ABI no garantiza estabilidad; no exponer tipos Rust, trait objects, allocator o panics entre binarios compilados independientemente. No cargar código no confiable en compositor.
## Diseño
Preferir manifest declarativo + proceso externo con IPC versionado; WASM Component Model/WIT candidato para lógica portable con imports explícitos y límites, no reemplaza sandbox/política del host. Para integración nativa inevitable dentro de proceso confiable: ABI C pequeño y versionado, repr(C) donde corresponda, handles opacos, ownership y funciones de liberación del mismo allocator, tamaño/versión de struct, códigos de error, no unwinding entre fronteras; no prometer estabilidad sin pruebas. Mantener plugins de terceros fuera de proceso crítico; Qt QPA caso específico fijado por versión, no contrato general. Negociar major/minor, capability flags, schemaVersion, fallback/rechazo explícito, lifecycle, restart y rollback. Firma/procedencia no concede permisos; mantener licenses y SBOM. Reusar SupraTrust y catálogo de acciones, no segundo mecanismo.
