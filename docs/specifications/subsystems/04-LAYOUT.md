# S04 — SupraLayout
Fuentes: [Taffy API](https://docs.rs/taffy/latest/taffy/), [Taffy Parley example](https://github.com/DioxusLabs/taffy/tree/main/examples/parley), [AppKit WWDC26](https://developer.apple.com/videos/play/wwdc2026/289/).
## Diseño
Árbol de layout independiente del backend gráfico; entrada constraints min/max, tamaño intrínseco, baseline, padding, gap, alignment, dirección, expansión/compresión y prioridades. Medición de texto/imágenes por callbacks puras y caché con invalidación. Candidato Taffy para flex/grid, extensiones propias para prioridades tipo hugging/resistance, alignment guides, split views y concentricidad. No asumir equivalencia a Auto Layout. Comparar algoritmo de restricciones lineales (Cassowary/kiwi candidatos) solo si necesidad real de restricciones globales. Evitar ciclos measure-layout y bucles al resize; diagnóstico explícito de restricciones contradictorias. Clipping, overlays y popovers separados de flujo; transformaciones coherentes con hit testing.
LayoutSnapshot inmutable por revisión, rectángulos lógicos, baseline, clip, transformación y z-order; renderer, input y accesibilidad consumen misma revisión. Rounding determinista al rasterizar por escala, no redondear cada nodo acumulando errores. Dirty subtree, caché por restricciones y fuente, medir crecimiento. UI semántica no depende de píxeles. No diseñar toolkit universal antes de prototipo.
S04a: constraints, intrínseco, baseline, RTL, texto largo, shrink/expand, concentricidad. S04b: tamaños y escalas 1/1.25/1.5/2, resize, comparación ROI, hit test y a11y. S04c: layout incremental vs recompute, p95 en árboles 100/1k/10k, sin ciclos. S04d: misma interfaz en Taffy y candidatos; conservar o adaptar según evidencia.
