# S11 — SupraSession y recuperación
Fuentes: [systemd desktop environments](https://github.com/systemd/systemd/blob/main/docs/DESKTOP_ENVIRONMENTS.md), [systemd.special](https://www.freedesktop.org/software/systemd/man/latest/systemd.special.html), [xdg-session-management](https://wayland.app/protocols/xdg-session-management-v1), [XDG Autostart](https://specifications.freedesktop.org/autostart/latest/).
## Diseño
Gestor login/PAM/logind existente, sesión Wayland alternativa. Compositor listo (socket, outputs, interfaces críticas) antes de anunciar readiness; supervisar servicios de usuario por lifecycle y dependencia, no asumir graphical-session.target implica socket listo. Session target, propagación de entorno Wayland/D-Bus con cuidado de sesiones simultáneas; no detener servicios ajenos ni sustituir portales host. Autostart único mecanismo y reglas XDG. Timeouts/backoff, límites de reinicio, safe mode sin extensiones, fallbacks. Lock fail-closed; caída de compositor puede cerrar clientes, retorno controlado al login.
Persistencia: preferencias, dock, workspace ID/orden, ventanas cooperativas con app_id+session ID, outputs reconciliados, geometría lógica y estado app propio; guardar atomic y esquema versionado. Restaurar solo con consentimiento/preferencia; no relanzar tareas sensibles o acciones externas automáticamente. xdg-session-management permite restaurar toplevel state de clientes cooperativos, no memoria de procesos ni documentos no guardados. Aplicaciones propias guardan tabs/navegación; recuperación de documentos es responsabilidad app. No afirmar continuidad transparente.
S11a: readiness, startup/logout, dos sesiones, autostart sin duplicar. S11b: kill shell, crash service, backoff, config inválida; lock sigue seguro. S11c: compositor cae, sesión nueva, restauración cooperativa y apps no cooperativas; sin pérdida de archivos de prueba. S11d: monitor desconectado, rollback config, update y desinstalación. Intel/AMD/NVIDIA y VM separados.
