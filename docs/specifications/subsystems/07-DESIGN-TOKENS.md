# S07 — SupraTokens
Fuentes: [DTCG 2025.10 format](https://www.designtokens.org/tr/2025.10/format/), [resolver](https://www.designtokens.org/tr/2025.10/resolver/), [technical reports](https://www.designtokens.org/tr/2025.10/). Especificación de grupo comunitario W3C, no recomendación formal W3C.
## Diseño
Separar primitive, semantic y component tokens; estado/variante mediante resolución explícita. Tipos color (espacio+canales+alfa), dimension (unidad lógica/física), font, duration, cubicBezier, shadow y composite. Extensiones propias versionadas para material óptico, spring, curva de geometría, blend y calibración de backend. Mantener DTCG compatible donde cubra el tipo; no atribuir extensiones a estándar. Registro de medición de referencia, procedencia, incertidumbre y estado separado de token operativo. Ningún número histórico no verificado se promueve automáticamente.
Compilador Rust candidato: parse/schema -> grafo de alias -> resolución por contexto -> validación de tipos, unidades, rangos y ciclos -> IR canónico -> generadores deterministas Rust, GLSL, Qt/QML, GTK CSS y documentación/JSON. Backend informa capacidades no representables (p.ej. refracción en CSS), no oculta aproximación. Archivos generados con hash y aviso no editar; CI regeneración y diff. Preferencias seleccionan variantes y overrides autorizados, no recompilar shaders por cada color.
S07a: alias, ciclo, inexistente, tipo incorrecto, conversión de unidades. S07b: light/dark/accent/contrast, snapshots por backend, compatibilidad de esquemas. S07c: determinismo, regeneración CI, cambio de token visible en todas UIs; degradación explícita. S07d: prueba de color/geometry ROI y vinculación de evidencia. No implementar valores Apple no medidos.
