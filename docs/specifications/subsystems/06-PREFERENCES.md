# S06 — SupraPreferences
Fuentes: [Settings portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Settings.html), [backend Settings](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.impl.portal.Settings.html), [GtkSettings](https://docs.gtk.org/gtk4/class.Settings.html), [XDG base directories](https://specifications.freedesktop.org/basedir-spec/latest/).
## Diseño
Propietario por dominio, servicio de preferencias con esquema versionado y snapshots; defaults, preferencias de usuario, override temporal autorizado, políticas del sistema separadas y precedencia explícita. Apariencia, dock, ventanas, input, sonido, privacidad y accesibilidad. Red/energía siguen autoridad de servicios upstream, no duplicar estado. Secretos mediante servicio de credenciales, no configuración JSON.
Validate -> persist atomic (archivo temporal y reemplazo o transacción SQLite según ADR) -> publicar revisión/evento -> ack/reconciliación; no prometer atomicidad distribuida de múltiples servicios. Cada consumidor mantiene última configuración válida y se resincroniza; proteger contra escritura concurrente con expected revision. Migraciones versionadas, backup, recuperación, reset por categoría, exportación redactada. Backend de portal expone settings estandarizados read-only y señales, no escritura arbitraria. Adaptadores GTK/Qt/XSettings transforman preferencias con feedback loop evitado. Tema automático por horario/config local; accesibilidad/contraste son restricciones. Cambios de pantalla con preview/confirmación/revert. Agentes invocan acciones tipadas y permisos del recurso, no editan archivos internos.
S06a: validación, cambios concurrentes, escritura interrumpida, migración y reset. S06b: cambios live, clientes desconectados, rollback, última revisión válida. S06c: portal y Qt/GTK, sandbox, política admin y permisos. S06d: arranque sin servicio y recuperación. Sin elección definitiva de storage.
