# S10 — Extensiones y widgets
Fuentes: [WASI capabilities](https://github.com/WebAssembly/WASI/blob/main/docs/Capabilities.md), [Wasmtime interruption](https://docs.wasmtime.dev/examples-interrupting-wasm.html), [GNOME extensions](https://extensions.gnome.org/about/), [COSMIC](https://github.com/pop-os/cosmic-epoch).
## Diseño
No cargar código de terceros en proceso compositor ni shell crítico. Preferir extensiones declarativas (manifest, UI tree, acciones y datos tipados), procesos separados para nativas, Wasm/WASI Component Model opcional para lógica portátil con imports restringidos; runtime no es garantía aislada por sí sola. Aislar proceso host y limitar memoria, CPU, duración, frecuencia, filesystem, red y datos. Wasmtime candidato con límites/fuel/epoch; medir overhead y revisar interfaz host. No habilitar permisos por simple instalación. Firma/procedencia y actualización verificables, compatibilidad de API, deshabilitar, rollback y safe mode; marketplace no necesario inicialmente.
Widget host renderiza SupraUI con layout/estados, semántica, modo claro/oscuro, tamaños, calendario/reloj local, eventos limitados y actualización bajo demanda. Los widgets no reciben framebuffer o contenido de otras apps. Datos sensibles ocultos en lock. Extensiones Files/Search/Preview/Share registran capacidades específicas, no comandos root. Reusar SupraActions y SupraTrust; no crear mecanismo alternativo de permisos.
S10a: manifest y versionado, instalar/desactivar, widget ejemplo local. S10b: timeout, agotamiento de cuota, crash, update incompatible, compositor continúa. S10c: revocación y recursos fuera de permiso, red denegada, fixtures; no confiar solo en firma. S10d: layout, batería/idle, accesibilidad y apariencia.
